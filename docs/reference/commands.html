Command Reference

The bazel commands, flags, target patterns, and query functions this course uses, with what each is for. This page is for looking things up; the modules teach each one properly.

⏱ Look things up as you goBazel 9.3.2 through Bazelisk
  • Pick the right command: build, run, test, query, cquery, aquery, mod, info, clean
  • Find the flag that changes configuration, test selection, or output
  • Write target patterns and query expressions without guessing

Running Bazel in this course

Pixi installs Bazelisk, which reads .bazelversion and runs that Bazel (9.3.2 everywhere here). Inside this repository, pixi run bazel ... works from any directory; pixi shell puts bazel on PATH for a whole session.

pixi run bazel version          # which Bazel Bazelisk runs
pixi run bazel build //...       # build every rule target in the main repository
pixi run bazel test //...        # build, then run every non-manual test

For a workspace outside this repository: pixi add bazelisk, write 9.3.2 to .bazelversion, and run pixi run bazelisk ....

Everything a command does is bazel [startup options] <command> [options] <targets>. Bazel rejects options it does not know (ERROR: --name :: Unrecognized option: --name), so arguments for your own program go after --.

Commands

CommandWhat it doesTaught in
bazel build PATTERNSLoads, analyzes, and runs the actions needed for the targets' outputs (under bazel-bin/).M01
bazel run TARGET -- ARGSBuilds one executable target, then runs it from its runfiles tree. ARGS go to your program; BUILD_WORKSPACE_DIRECTORY tells it where the workspace is.M01, M03
bazel test PATTERNSBuilds the targets, then runs the tests among them (and the tests their test_suites name). Unchanged tests report (cached) PASSED.M05
bazel coverage PATTERNSLike test, collecting coverage data.M05
bazel query EXPRAsks questions of the target graph before configuration: every branch of every select(), plus implicit and toolchain dependencies.M09
bazel cquery EXPRQuery after configuration: select() resolved for the flags you pass. Labels print with a configuration id, such as //app:hello (a7a71fd).M06, M09
bazel aquery EXPRThe actions (commands, inputs, outputs, mnemonics) analysis creates.M09
bazel mod graph, bazel mod deps MThe resolved Bzlmod dependency graph, as a tree.M04
bazel info [KEY]Paths and settings: bazel-bin, output_base, execution_root, ...M02
bazel fetchDownloads external repositories without building.M04
bazel cleanDeletes outputs. Almost never needed: the cache is keyed by content. --expunge also deletes fetched repositories.M02
bazel shutdownStops this workspace's Bazel server (it otherwise idles in memory).M02
bazel versionPrints the Bazel version.M00

Target patterns

PatternMeans
//app:helloOne target. //app is short for //app:app.
//app:allEvery rule target in the package app.
//app:* or //app:all-targetsEvery target in the package, files included.
//app/...Every rule target in app and every package below it.
//...Every rule target in the main repository (not files).
-- //... -//tools/...Exclusion. Negative patterns are only allowed after -- and apply left to right: -- -//tools/... //... adds the excluded targets back.

Wildcards (..., :all, :*) skip targets tagged manual; name one explicitly to build it. A test_suite that lists a manual test still runs it.

Without --, a negative pattern is an error: bazel build //... -//tools/... prints ERROR: Invalid options syntax: -//tools/....

Common flags

Configuration (changes what is built)

FlagEffect
-c opt (--compilation_mode)fastbuild (default), dbg, or opt. Matched by config_setting(values = {"compilation_mode": "opt"}).
--define=key=valueA free-form key matched by config_setting(define_values = {...}).
--//pkg:flag=value, --//pkg:flag, --no//pkg:flagSets a user-defined build setting (bool_flag, string_flag from bazel_skylib).
--platforms=//:linux_arm64The target platform; select() on constraint_values follows it.
--config=NAMEExpands the build:NAME (and common:NAME, test:NAME, ...) lines of .bazelrc.

Tests

FlagEffect
--test_output=errors|all|streamed|summaryHow much test output to print. errors shows the log of failing tests.
--test_tag_filters=-slow,integrationRun only tests with (or, with -, without) these tags. Size counts as a tag.
--test_size_filters=small,mediumRun only tests of these sizes.
--build_tests_onlyBuild only the tests that will run, not every target matched.
--test_filter=NAMEPassed to the test as TESTBRIDGE_TEST_ONLY; the test framework decides what it means.
--test_arg=ARGAn argument for the test program (repeat for several).
--runs_per_test=N, --nocache_test_resultsRerun tests to hunt flakiness; ignore cached results.

Builds and debugging

FlagEffect
--keep_going (-k)Keep building independent targets after an error.
--nobuildStop after analysis: checks the graph without running actions.
--verbose_failuresPrint the full command line of a failing action.
--disk_cache=PATHA local cache shared between workspaces and bazel cleans.
--explain=FILE --verbose_explanationsWrites why each action ran (for example "no entry in the cache").
--announce_rcPrints which .bazelrc lines applied.
--toolchain_resolution_debug=REGEXExplains toolchain selection ("No matching toolchains found").

Put team-wide flags in a checked-in .bazelrc (common --keep_going, test --test_output=errors, a build:ci config) instead of shell aliases, so every developer and CI run the same build.

Query functions

Quote query expressions in the shell: bazel query 'deps(//app:hello)'. Results are sorted labels (by package, then name: //tools:gen before //tools/exp:x).

ExpressionReturns
deps(X), deps(X, N)X and everything it depends on (to depth N).
rdeps(U, X), rdeps(U, X, N)Targets in universe U that depend on X: "what breaks if I change this?"
allrdeps(X)Reverse deps in the whole loaded graph; requires --universe_scope=//... (or --infer_universe_scope), otherwise it is an unknown function.
somepath(A, B), allpaths(A, B)One path, or every target on any path, from A to B.
kind(REGEX, X)Targets whose kind matches, such as py_test or "source file".
attr(NAME, REGEX, X)Targets whose attribute matches, such as attr(tags, manual, //...).
filter(REGEX, X)Targets whose label matches.
labels(ATTR, X)The labels in one attribute, such as labels(srcs, //app:hello).
tests(X)The tests in X, with test_suites expanded.
siblings(X)Every target in the packages of X.
buildfiles(X)The BUILD and .bzl files that define X.
set(A B C)A literal set of labels (space-separated).
X + Y, X - Y, X ^ YUnion, difference, intersection (also union, except, intersect). Write spaces around -: //...-//a/... is one (invalid) pattern.

Output formats

FlagPrints
--output=label (default)//app:hello
--output=label_kindpy_binary rule //app:hello
--output=packageThe packages of the results: app
--output=buildEach rule as it would appear in a BUILD file (with macros expanded).
--output=location/path/to/ws/app/BUILD.bazel:2:10: py_binary rule //app:hello (absolute path)
--output=graphGraphviz dot.
--output=xml|proto|streamed_jsonprotoMachine-readable forms for tools.
cquery --output=filesThe output files a target produces, such as bazel-out/k8-fastbuild/bin/a/g.txt.

--noimplicit_deps hides most implicit dependencies (toolchains, launchers); --notool_deps hides tools built for the execution platform.

The in-page simulator supports query and cquery with --output=label, label_kind, and package, and the functions above. It does not show implicit or toolchain dependencies, and it has no aquery: use a lab for those.
