Static code

Static code uses Prism highlighting. Escape <, > and & inside <pre>. data-label names the file or says where the text came from.

load("@rules_python//python:defs.bzl", "py_binary")

py_binary(name = "hello", srcs = ["hello.py"])
pixi run bazel build //app:hello
INFO: Build completed successfully, 0 total actions

Sandboxes

A sandbox is a small workspace evaluated by the in-page simulator. Each textarea.file is one file; data-readonly locks it and data-hidden keeps it out of the tabs. Every command in data-commands becomes a button.

Exercises

An exercise is a sandbox with checks: test_*(bazel) functions run against the learner's files. The solution must pass and the starter must fail at least one check (pixi run check-exercises).

//app:hello depends on //lib:greet, but the library is private to its package. Make it visible to //app only (not public), so bazel build //app:hello succeeds.

Hint

A visibility label of the form //pkg:__pkg__ names one package.

Show solution 
load("@rules_python//python:defs.bzl", "py_library")

py_library(
    name = "greet",
    srcs = ["greet.py"],
    visibility = ["//app:__pkg__"],
)

Labs

A lab is graded by real Bazel on the learner's machine. The widget adds the pixi run start and pixi run grade commands; the workspace and checks live in labs/<id>/. This one is Module 00's lab, shown here for its markup.

Make bazel run //hello:hello print a greeting and bazel test //... pass.

  • Run pixi run start m00-lab1
  • Fix the BUILD file in work/m00-lab1
  • Run pixi run grade m00-lab1
